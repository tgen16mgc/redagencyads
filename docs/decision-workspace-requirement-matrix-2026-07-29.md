# Decision Workspace Requirement Matrix

Date: 2026-07-29

Status meanings:

- `Implemented`: the product path, validation, and local automated evidence exist.
- `External validation`: the product path exists, but the acceptance criterion needs production credentials, telemetry, delivery infrastructure, or client outcome data.
- `Infrastructure pending`: the repository has the job contract, but the named production orchestrator is not operated here.
- `Backlog`: intentionally represented as an unavailable connector contract.

Deployment boundary: the repository defaults to local JSON/file stores for pipeline snapshots, watchlists, creative assets, action audits, experiments, prompts, and acceptance evidence. `DECISION_WORKSPACE_DATA_DIR` now places every default store beneath one root, and `compose.yaml` mounts that root as a persistent volume. Database/object-storage declarations are deliberately rejected until a real adapter exists. Deployable Airflow DAGs cover connector sync, backfill, digest, budget operations, and learning-phase resume, but an operating scheduler is still external infrastructure.

Current local acceptance snapshot: `.env.local` configures the Apify public-data path, but not TikTok CCL/partner credentials, Google Ads/YouTube/GA4 credentials, LinkedIn credentials, cron/webhook delivery, creative inference, or a Meta system-user token. Those live acceptance criteria are therefore not claimed by this matrix.

Executable completion evidence: `GET /api/readiness` and `npm run verify:decision-workspace` evaluate every `External validation` row. Traceable evidence can be recorded through the operator-token-protected endpoint or `npm run record:decision-workspace-evidence`; successful GA4, provider-inference, and pacing-alert routes also self-record evidence inside the dual-declared production boundary. Local or non-production evidence cannot pass a gate. Deployment and certification steps are documented in `docs/decision-workspace-production-runbook.md`.
